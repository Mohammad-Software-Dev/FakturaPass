# Validator source and notice evidence

Run `npm run validator:source-evidence -- sha256:<immutable-image-id>` with Python 3, Git, curl, Docker and access to the pinned upstream sources. This independent review command does not build, publish or deploy an image. It writes a packet under `.data/releases/validator-sources-<timestamp>/` and writes `source-evidence.json` only after all checks pass. Partial directories are not completed packets. The report records its source revision and whether the checkout was dirty.

The lock at `services/invoice-engine/metadata/sources.lock.json` pins the current Linux ARM64 JRE archive hash, exact JDK source commit, 31 individual source hashes, the Saxon 12.9 source/distribution archive hashes, and the annotated preferred-source tag and commit. Run `npm run engine:setup` first if `vendor/config.zip` is absent; its bytes must match the dependency lock. Another architecture or dependency update requires its own verified lock evidence; this command does not silently accept another binary. Downloads require HTTPS and immutable Git commit URLs. No upstream program is executed and archive entries are not extracted into arbitrary filesystem paths.

The collector reads the exact image's JRE build metadata and requires the expected version, repository and source reference. It verifies jrt-fs bytes, maps every installed class (including inner classes) to exactly one source file and rejects missing, extra or ambiguous source records. Each source is hash-checked and must retain the expected GPL version 2 only and Classpath exception header. The original JRE LICENSE, ADDITIONAL_LICENSE_INFO and ASSEMBLY_EXCEPTION are included. This establishes source/header correspondence; it does not claim a reproduced JRE build or complete source distribution for the entire runtime.

For Saxon, the installed Maven JAR hash is pinned. The collector retains the matching upstream source ZIP and binary distribution with all its notices. Every member payload of the distribution JAR is compared with the installed JAR. Only the manifest and two named signature files may differ; changed class or resource bytes fail. Original notices remain intact, including notices for upstream distribution components not installed by FakturaPass. Their presence is not a statement that every upstream component is shipped.

## Remaining review and release sequence

The installed archive's missing scanner declaration is now supported by exact-source header evidence, but the permissive-only policy still blocks it. Saxon's MPL-2.0 remains outside that policy too. No allowlist expansion, legal approval or exception has been recorded.

[Saxonica distinguishes its preferred-form source repository from the preprocessed release ZIP](https://www.saxonica.com/html/documentation12/conditions/index.html). The initial packet retained only the latter. The continuation below now retains both forms. Review the intended distribution model and remaining attribution gaps, and record the applicable license/notice decision before changing a gate. See [the upstream Adoptium FAQ](https://adoptium.net/docs/faq) for the general runtime licensing declaration; the retained exact-source headers provide the package-specific evidence.

After those reviews, rebuild matching web, worker and validator images and repeat combined security and functional acceptance. Registry signing, staging/rollback and production acceptance remain separate. This source packet is neither a release manifest nor a legal clearance.

Files without matching text explicitly require review; keyword matching does not determine licensing. No archives are extracted into arbitrary paths.
