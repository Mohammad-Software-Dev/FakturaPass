## Findings, in priority order

1. **Incorrect amount label for prepayments.** The brand invoice header labels €2,239.98 as “Invoice total including VAT.” Its actual gross total is €2,739.98, less a €500 prepayment. The overview shows net €2,302.50, VAT €437.48 and amount due €2,239.98 without explaining the subtraction. Show gross total, prepayment and outstanding amount explicitly; label the header amount correctly.
2. **Financial adjustments are hidden.** Office-equipment line amounts total €2,741.00, but the displayed net is €2,603.95. The €137.05 project discount and its reason are absent from the overview. Display discounts/charges between the line subtotal and taxable total.
3. **Editing requires raw JSON.** “Corrected revision” opens a prepopulated code editor, with no ordinary fields for dates, references, parties or items. Saving a new revision works and preserves history, but it is cumbersome and error-prone for customers. Provide a structured editor with validation feedback and a before/after summary; keep JSON in an advanced view.
4. **The import preview is not enough for review.** It contains invoice number, recipient, outstanding amount, source identifiers, date and item count. Seller, actual items, VAT, adjustments, prepayment, payment terms and references are absent. The changed buyer reference was also invisible in the correction preview. Reuse a complete readable invoice preview before saving, including the changed fields.
5. **Duplicate recovery stops at advice.** The consulting import said “This source has already been imported. Open the invoice and create a correction,” but supplied no link/button to do so. A manual return to the list and search was necessary. Provide “Open existing invoice” directly in the message.
6. **Correction starts with misleading empty-preview copy.** Even with the full existing JSON already populated, the preview says “Select the source first.” There is no explicit return-to-invoice/cancel action; the available back action leads to the invoice list. Initialize the preview and offer a clear cancel/back-to-invoice action.
7. **The happy path is usable, but needs plain-language guidance.** The progress indicator and changing primary action successfully guide Validate → Approve revision → Generate XRechnung → Download XML. Explain what approval means and, after generation, say the invoice is ready to download and has not been sent. The artifacts screen currently emphasizes checksums and validator details without a handoff explanation.
8. **Some overview details remain technical or incomplete.** Quantities use C62/HUR rather than readable units; the “Item / description” table omits the supplied descriptions. Contract references and payment details are not shown alongside the purchase-order reference. Expose these where present, without forcing users into JSON.

## Overall assessment

The workflow functions, and immutable corrections and download handoff worked in this review. The visual hierarchy is restrained and consistent. It is not yet seamless for a typical customer: financial clarity and form-based editing should be addressed before describing the experience as finished. The prepayment amount label is a correctness issue, not merely visual polish.

This manual review used English/light mode in the in-app browser. It is not a new cross-browser, mobile, accessibility or complete regression test run. Existing consulting validation was inspected rather than recreated. No invoice was sent to a recipient.

## Resolution

The follow-up implementation addresses the findings above:

- A shared invoice review renders seller/buyer addresses, item descriptions and readable units, references, payment information, line subtotal, adjustments with reasons, VAT, gross total, prepayments, rounding and amount due. The header now labels the outstanding balance as “Amount due.” Narrow previews and mobile screens show item cards without horizontal scrolling.
- A grouped form edits invoice details, parties, existing items, amounts, adjustments and payment information. Invalid schema values have inline feedback. JSON remains available under an advanced disclosure; editing it clears stale form state until the next successful preview.
- Explicit recalculation uses decimal arithmetic and the currently supported 19% VAT case. It preserves the stated discount bases and prepayment; it never silently repairs an imported invoice or changes the original source file. Users review the resulting preview before saving.
- Corrections open with a populated preview and provide a before/after change list and a cancel-to-invoice action. Existing immutable revision and approval rules remain in force.
- Duplicate responses contain the existing invoice ID, scoped to the current tenant and environment. The UI offers “Open existing invoice.”
- Workflow guidance explains approval, generation and the final download handoff, explicitly stating that the invoice has not been sent.
- German and English catalogs and the user guide cover the revised experience. Regression coverage includes the three examples, duplicate recovery, cancellation, correction, official validation/generation/download, decimal recalculation, inline errors, language switching, mobile sizing and dark-mode screenshots.
