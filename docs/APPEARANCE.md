# Appearance

Light and dark modes use one semantic CSS palette: crisp porcelain and cobalt accents in light mode, midnight navy surfaces with soft blue highlights in dark mode. Editorial serif page titles contrast with readable sans-serif controls and tabular financial values. Status colors retain distinct success, error and pending meanings; labels remain visible so color is not the only signal.

The top-bar appearance button switches immediately without remounting the workspace. Its pressed state and translated label are available to assistive technology. A first-party `fakturapass-theme` cookie persists the explicit choice for one year; the server includes `data-theme` on the initial HTML to avoid a light flash on a dark reload. Light is the default; an invalid preference falls back to light. Both themes expose native `color-scheme` for browser controls.

Colors are defined as semantic variables at the start of `apps/web/app/globals.css`; change the corresponding role in both palettes instead of introducing component-specific hex colors. Reduced-motion preferences disable transitions. Browser checks cover persistent preferences, draft preservation, server-rendered theme, mobile layout, representative text contrast, and complete dark-mode invoice workflows. Screenshot outputs are generated by the theme browser tests.

See USER_GUIDE.md for narrative walkthroughs of the application's supported scenarios.

The customer workspace prioritizes own-file imports and invoice actions. Demo identity banners and test-case selectors are removed. A fictional format example is available inside a collapsed help section, and installation/version details are disclosed in Settings rather than repeated across primary screens. Existing source records and archived evidence remain unchanged.
